# x402 plugin

Sign x402 payment challenges using hiero-cli managed keys. The payer private key never leaves the KMS — the command builds and signs a transfer but does **not** submit it; the x402 facilitator adds its fee-payer signature and submits.

## End-to-end flow (agent-driven)

The CLI does **not** make HTTP requests. The agent runs them:

1. **GET** the target URL.
2. If status `402`, read the `PAYMENT-REQUIRED` response header (header names are case-insensitive). Decode/inspect its payload — confirm `x402Version` is `2` and `accepts[]` contains a `scheme: "exact"` entry whose `network` is `hedera:mainnet` or `hedera:testnet`. If not, this CLI cannot help.
3. Make sure the active hcli network matches the challenge network (`hcli network use <mainnet|testnet>`), otherwise signing fails.
4. Pass the **raw header value** to the CLI: `hcli x402 sign --challenge "<PAYMENT-REQUIRED value>"` (add `--asset` if the challenge offers several; `--from` for a non-operator payer).
5. Take `paymentSignatureHeader` from the output.
6. **Retry the same request** with header `PAYMENT-SIGNATURE: <paymentSignatureHeader>`.
7. The facilitator validates + submits; the retry returns the real `200` data.

```bash
# the agent runs these HTTP calls, not the CLI
HDR=$(curl -sD - -o /dev/null https://api.example.com/data | grep -i '^payment-required:' | cut -d' ' -f2-)
SIG=$(hcli x402 sign --challenge "$HDR" --format json | jq -r .paymentSignatureHeader)
curl -s -H "PAYMENT-SIGNATURE: $SIG" https://api.example.com/data
```

Requires a configured network and operator (or `--from` payer) — see the prerequisites in `SKILL.md`. The payer must be funded; balance/association are checked by the facilitator at settlement.

---

### `hcli x402 sign`

Decode a `PAYMENT-REQUIRED` header, build a partially-signed Hedera `TransferTransaction` (debit payer / credit `payTo`; HBAR `0.0.0` or an HTS token), KMS-sign it, and return the `PAYMENT-SIGNATURE` header value.

| Option          | Short | Type   | Required | Default        | Description                                                                                                                      |
| --------------- | ----- | ------ | -------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `--challenge`   | `-c`  | string | **yes**  | —              | Value of the `PAYMENT-REQUIRED` header from the 402 response                                                                     |
| `--from`        | `-f`  | string | no       | operator       | Payer: `accountId:privateKey`, key reference `kr_xxx`, or account alias. Defaults to network operator                            |
| `--asset`       | `-a`  | string | no       | —              | Asset to pay with when the challenge offers several. `0.0.0` = HBAR, or an HTS token id. Required only on multi-asset challenges |
| `--key-manager` | `-k`  | string | no       | config default | Key manager: `local` or `local_encrypted`                                                                                        |

**Example:**

```bash
hcli x402 sign --challenge "<PAYMENT-REQUIRED value>" --from 0.0.5005
hcli x402 sign --challenge "<PAYMENT-REQUIRED value>" --asset 0.0.0
hcli x402 sign --challenge "<PAYMENT-REQUIRED value>" --asset 0.0.456858 --format json
```

**Output:** `{ paymentSignatureHeader, payer, payTo, amount, asset, network, feePayer, transactionId }`

**Notes:**

- Only x402 protocol version `2` and the `exact` scheme on `hedera:mainnet` / `hedera:testnet` are supported; anything else is rejected.
- The challenge network must equal the active hcli network, otherwise the command fails asking to switch network.
- If several Hedera `exact` requirements are offered, `--asset` is required to pick one.
- No client-side preflight: payer balance and token association are validated by the facilitator at settlement, after this command returns.
